# Architecture rules
- Homepage Google reviews use a public read server function and shared query cache; admin changes use the typed browser client with database-enforced admin policies to keep public reads safe and writes authorized.
- Google review ordering is saved atomically through an admin-only database function, and a database trigger plus unique index enforce one featured review, so concurrent edits cannot leave partial ordering or multiple featured reviews.
- Review QR codes are rendered locally with qrcode.react from the shared Google review destination, avoiding external QR image services and keeping all review links consistent.- Structured listing details live as nullable columns on listings, shared through src/lib/listing-details.ts (amenity list, AI prompt, normalization, flag rules); owners' original text sits in the admin-only listing_source_descriptions table so it can never leak through public listing reads.
- Listing description conversion runs in the admin-checked /api/convert-listing server route (bearer token + has_role), so AI calls and the API key stay server-side; public About falls back to stored description when empty.
- Admin listing saves use the shared description-generation helper and admin-specific schema, so hidden descriptions never block Save while other forms retain their validation.
- Retired listing details are omitted from write payloads and active-detail detection; conversion filters new amenities to the shared list and merges existing amenity details, so legacy data survives edits.
- Retired Feedback and static reviewer URLs retain redirect-only TanStack routes, so old deep links stay valid without keeping their content.
- The public Google reviews query returns the admin-saved view-reviews destination separately from the shared write-review/QR destination, so clearing the view link hides only its button.
